01 / THINK FROM THE NEED

第一性原理：先看目标，再决定方案

3-6 分钟

先用一句话说明：你要在什么情境下，把屏幕上的哪段信息保存下来？截图工具的名字和功能数量，都不能代替这个问题。

选读图解：从腾讯文档理解第一性原理

第一性原理思考：把问题拆成有证据的事实和必须满足的约束，区分哪些只是习惯性假设，再重新设计并验证。追问“为什么”是工具，证据与验证才让推理站得住。

腾讯文档：一起写方案，一定要来回传文件吗？

两位同学各改一份活动方案，再发给负责人，谁来合并？先问：用户真正要的是“传文件”，还是“共同完成一份内容一致的方案”？腾讯文档的多人实时在线编辑，提供了共同修改同一份文档的现成路径。

思考步骤这个案例怎样做
真正目标多人共同完成一份方案，并知道当前内容是什么。
事实与约束官方确认支持多人实时编辑；设计仍要处理网络、权限与同时修改。
可质疑的假设“每人必须先保存独立副本，最后交给一个人合并。”
重新设计让成员进入同一份共享文档，围绕共同内容协作。

怎样验证：设计两人各改一段、同时改同一句、未获编辑权限者尝试修改三个测试，观察最终内容与提示。这个选读案例不要求注册账号或开发文档软件；今天实际开发和测试的作品是截图工具。这里是对产品功能的方法复盘，不是开发团队的研发过程自述。

事实来源：腾讯官方产品介绍 ↗

自检：把文档搬到网页上就够了吗？
先回答，再对照：不够。两个人若仍各改一份副本，合并问题依旧存在。改变的是协作流程；网络、权限和修改冲突仍要考虑。

今天的基本目标：把屏幕上的一块信息保存成图片，并且知道图片在哪里。你不需要复制 QQ 截图的全部功能。

要分清的事情本课截图工具
已观察的事实回想或演示一次自己的截图和找图过程，记录发生了什么。
待验证的假设“找不到保存的图片”可能比“截不了图”更麻烦，需要实际观察。
本次约束Windows、本地使用、单显示器、普通用户权限，课堂时间有限。
可以改变的方案明确显示保存路径，不必先做账号、OCR 和云同步。

用一句话写下：“我想帮助【谁】，在【什么情境】截取【什么信息】，并能【保存和找到它】。”暂时没有证据的判断标为待验证。作品中的一个小细节由你决定，例如窗口标题、默认文件名前缀或保存成功提示。

03 / START SMALL

MVP：先完成一个能用的最小版本

05 / VERIFY AND ITERATE

验证与迭代：让证据说话

36-42 分钟
场景你要亲自做什么通过时应看到什么
正常流程准备写有“TEST + 自己姓名”的页面；框选、保存 PNG，再打开。区域与内容正确，没有遮罩；文件可打开，能找到保存位置。

Everything 是 Windows 文件搜索软件。官方文档说明，它索引文件名和路径，并维护变化；搜索时可以利用这些索引。由此复盘：如果目标只是按名称找文件，就不必把“读懂每个文件正文”作为前提。


重新拆解这个软件需求
目标：凭部分文件名找到文件位置。
必要信息：文件名、路径，以及文件是否已改名或删除。
可质疑的假设：每次搜索都必须重新从头读取目录。
替代方案：先建立索引，查询索引，并更新发生的变化。


边界也要写清：官方说明 content: 可搜索正文，但正文不在索引中，因此可能很慢。文件名搜索快，不等于任何信息都能立刻查到。本例只研究产品设计；免费软件不等于开源项目，不能默认复制其源码。
